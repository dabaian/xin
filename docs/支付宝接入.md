# 支付宝扫码充值接入

本项目用的是**当面付（`alipay.trade.precreate`）**：服务端预下单拿到 `qr_code` 字符串 → 前端渲染成二维码 → 用户用支付宝 App 扫码 → 支付宝异步通知 → 验签入账。

不用跳转收银台，用户体验最好，也不需要 H5/PC 网站支付那套重定向。

---

## 1. 签约当面付

1. 登录 [支付宝开放平台](https://open.alipay.com/)（企业/个体工商户主体）
2. 控制台 → **产品中心** → 搜索「当面付」→ 签约
   - 需要：营业执照、经营场所照片、结算账户
   - 审核通常 1–3 个工作日
3. 控制台 → **应用管理** → 创建应用（选「网页/移动应用」）
4. 应用详情 → **开发设置** → 接口加签方式选 **公钥模式**（本项目按公钥模式实现，不是证书模式）
5. 记下 **APPID**（形如 `2021xxxxxxxxxxxx`）

> 只有「已签约当面付 + 应用已上线」的 APPID 才能调 `alipay.trade.precreate`。
> 沙箱环境也支持，测试时把 `ALIPAY_GATEWAY` 换成 `https://openapi-sandbox.dl.alipaydev.com/gateway.do`。

---

## 2. 生成密钥（两个密钥别搞混）

### 2.1 应用私钥 / 应用公钥（你自己生成）

```bash
openssl genrsa -out app_private_key.pem 2048
openssl rsa -in app_private_key.pem -pubout -out app_public_key.pem
cat app_private_key.pem    # ← 这个填进 ALIPAY_PRIVATE_KEY_PATH
cat app_public_key.pem     # ← 这个要上传到开放平台
```

在开放平台「开发设置 → 接口加签方式 → 公钥」里，把 **应用公钥** 的内容粘贴进去。

### 2.2 支付宝公钥（平台给你的）

上传应用公钥后，页面会显示 **支付宝公钥**（一段 `BEGIN PUBLIC KEY`）。
把它复制下来，存成 `alipay_public_key.pem` —— 这才是 `ALIPAY_PUBLIC_KEY_PATH` 要指向的文件。

| 文件 | 来源 | 用途 |
|---|---|---|
| `app_private_key.pem` | openssl 生成 | 请求签名（`ALIPAY_PRIVATE_KEY`） |
| `app_public_key.pem` | openssl 生成 | 上传给支付宝，本地不用 |
| `alipay_public_key.pem` | 开放平台复制 | **通知验签**（`ALIPAY_PUBLIC_KEY`） |

90% 的「验签失败」都是把应用公钥当成了支付宝公钥。

## 3. 配置

```ini
ALIPAY_APP_ID=2021xxxxxxxxxxxx
ALIPAY_PRIVATE_KEY_PATH=/opt/muse-studio/secrets/app_private_key.pem
ALIPAY_PUBLIC_KEY_PATH=/opt/muse-studio/secrets/alipay_public_key.pem
ALIPAY_GATEWAY=https://openapi.alipay.com/gateway.do
ALIPAY_NOTIFY_URL=https://your-domain.com/api/payments/notify
ALIPAY_RETURN_URL=https://your-domain.com/wallet
ALIPAY_TIMEOUT=30m
ALIPAY_MOCK=0
```

```bash
sudo chmod 600 /opt/muse-studio/secrets/*.pem
sudo chown -R muse:muse /opt/muse-studio/secrets
sudo systemctl restart muse-studio
```

自检：

```bash
curl -b cookie.txt https://your-domain.com/api/payments/selfcheck
```

期望：

```json
{"ok":true,"alipay":{"configured":true,"app_id":"2021...","private_key_ok":true,
 "public_key_ok":true,"mock":false,"notify_url":"https://.../api/payments/notify"}}
```

## 4. 回调地址要求

`ALIPAY_NOTIFY_URL` 必须满足：

- 公网可访问，**必须是 https**（支付宝强制）
- 不能有登录态、不能被 WAF 拦、不能 302
- 返回纯文本 `success`（本项目已实现），否则支付宝会重试 8 次（25 小时内）
- Nginx 那一段 `location = /api/payments/notify` 必须关掉 `proxy_buffering`，否则支付宝等不到响应

---

## 5. 金额与积分

- **金额只由服务端按套餐决定**，前端只传 `package_id`，改前端也改不了价
- 金额单位全部是「分」（整数），库里 `amount_minor = 1000` 表示 10.00 元
- 1 元 = 10 积分，套餐里 `points` 就是到账积分（`bonus` 是额外赠送）
- 回调里的 `total_amount` 会与订单金额逐分比对，不一致直接拒绝入账并写审计日志

---

## 6. 幂等设计

```
payment_events.event_id = "alipay:<trade_no>:<trade_status>"  UNIQUE
```

- 同一笔支付回调重发 10 次 → 只有第一次入账
- 多进程/多并发也不会重复入账（靠数据库唯一约束）
- 回调丢失由后台 `PendingSweeper` 每 45 秒 `alipay.trade.query` 主动补单

可以自己验证一次：

```bash
# 同一笔已支付订单，把回调手工重放 5 次，余额应该只加一次
for i in 1 2 3 4 5; do
  curl -s -X POST https://your-domain.com/api/payments/notify -d "out_trade_no=MS...&trade_status=TRADE_SUCCESS&..."
done
```

## 7. 没有密钥时怎么先验收

```ini
ALIPAY_MOCK=1
```

- 下单不调支付宝，二维码里放一个占位链接
- 弹窗里多一个「模拟支付（测试模式）」按钮，点一下直接入账
- 整条链路（订单 → 事件 → 账本 → 余额 → 流水 → 记录）都会真实走一遍

**上线前必须改回 `ALIPAY_MOCK=0`**，否则等于白送积分。

## 8. 沙箱测试

```ini
ALIPAY_GATEWAY=https://openapi-sandbox.dl.alipaydev.com/gateway.do
ALIPAY_APP_ID=沙箱 APPID
```

沙箱用「沙箱支付宝」App 扫码，买家账号在开放平台沙箱工具里能看到。
沙箱的回调地址必须是公网地址（可以用内网穿透临时顶一下）。

---

## 9. 退款

本项目**不自动退款**（当面付退款需要额外签约「退款」权限，且有商户风控）。

用户要退款时：后台 → 用户 → 调积分（负数扣回），再到支付宝商家后台按 `trade_no` 原路退。
订单表里 `provider_order_id` 就是支付宝 `trade_no`，直接搜即可。

---

## 10. 常见报错

| 报错 | 原因 |
|---|---|
| `sign check fail` / `isv.invalid-signature` | 私钥和上传到平台的公钥不是一对 |
| `验签失败`（回调） | 用了应用公钥而不是支付宝公钥 |
| `isv.insufficient-isv-permissions` | 应用没签约当面付，或应用未上线 |
| `ACQ.TRADE_HAS_SUCCESS` | 同一 `out_trade_no` 重复下单，本项目已做订单复用 |
| `isv.invalid-app-id` | APPID 与密钥不匹配（沙箱/生产混用） |
| 回调收不到 | `notify_url` 不是 https，或被 Nginx/WAF 拦住 |
| 二维码扫出来是空白 | `qr_image` 为空 → `precreate` 没返回 `qr_code`，看日志 `logs/app.log` |
