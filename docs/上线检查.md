# 上线检查 · 模拟能力已全部关闭

这一版不再有「没配好就自动降级到模拟」的路径。所有模拟 / 演示能力都收敛到
一个开关文件：`backend/app/guard.py`，由程序在启动阶段硬拦。

本文分三部分：**改了什么**、**上线要做什么**、**出问题怎么对**。

---

## 一、这一版关掉了什么

| 项 | 以前的坑 | 现在 |
|---|---|---|
| 模拟支付 | 没配支付宝密钥就自动走模拟通道，任何人点一下就白拿积分 | 生产环境模拟通道**不注册**，`/api/payments/mock-pay` 这条路由根本不存在 |
| 模拟支付的开关 | 靠人记得改 `ALIPAY_MOCK=0`，忘了就资损 | `APP_ENV=prod` + `ALIPAY_MOCK=1` → **拒绝启动**，退出码 2 |
| 验证码回显 | 只要 `APP_ENV != prod` 就自动把验证码显示在页面上，等于没验证邮箱 | 必须显式 `MAIL_ECHO=1`，且生产环境这么写会**拒绝启动** |
| 安装脚本自动开 mock | `install.sh` 发现没填支付宝就看自己把 `ALIPAY_MOCK` 改成 1 | 已删除这段逻辑，安装后默认真实收款状态 |
| 管理员默认口令 | `ADMIN_PASSWORD` 留空就退回内置口令 | 生产环境留空 → **拒绝启动** |
| 上游密钥缺失 | 只是打条 warning，线上表现是「每单都失败」 | 生产环境缺失 → **拒绝启动** |
| 邮件服务缺失 | 静默失败，用户卡在注册页 | 生产环境缺 SMTP 且 `EMAIL_CODE_REQUIRED=1` → **拒绝启动** |
| API 文档 | `/api/docs` 一直开着，给扫描器看路 | 生产环境自动关闭（404） |

**唯一保留的例外**：`APP_ENV=dev`（或任何非 prod 值）下，显式写
`ALIPAY_MOCK=1` / `MAIL_ECHO=1` 仍然可用，方便本地把「下单 → 扫码 → 到账 → 扣费」
整条链路跑一遍。这是给开发用的，不影响线上。

## 二、上线要做什么

### 2.1 生产 `.env` 必填项

```ini
APP_ENV=prod                       # 少了这一项，守卫不生效
PUBLIC_BASE=https://你的域名.com    # 必须 https

MUSE_BASE=http://127.0.0.1:18610
MUSE_KEY=号池密钥                   # 必填

ADMIN_USERNAME=admin
ADMIN_PASSWORD=至少12位的强密码      # 必填

# 邮箱验证码：不配 SMTP，注册走不通
EMAIL_CODE_REQUIRED=1
SMTP_HOST=smtp.qq.com
SMTP_PORT=465
SMTP_USER=你的邮箱@qq.com
SMTP_PASS=授权码                    # 不是登录密码
SMTP_SSL=1
MAIL_ECHO=0

# 支付：二选一
ALIPAY_APP_ID=2021xxxxxxxxxxxx
ALIPAY_PRIVATE_KEY_PATH=/opt/viora-ai/secrets/alipay_private_key.pem
ALIPAY_PUBLIC_KEY_PATH=/opt/viora-ai/secrets/alipay_public_key.pem
ALIPAY_NOTIFY_URL=https://你的域名.com/api/payments/notify
ALIPAY_MOCK=0
# 或者暂时不收钱：
# PAYMENT_CHANNEL=none
```

### 2.2 启动，看这一行

```
运行状态：Viora AI · 环境 PROD · 支付宝当面付（真实收款） · SMTP 已配置
```

- 出现 `【模拟支付】不会真收钱` → 说明 `APP_ENV` 不是 prod，或者守卫没生效
- 出现 `充值已关闭（...）` → 没有可用通道，或你显式写了 `none`
- 出现 `【验证码回显】` → 验证码会显示在页面上，等于没验证
- 出现 `SMTP 未配置，邮箱验证码将发不出去` → 注册会失败

只有第一行那种形态才算配好了。

### 2.3 四条命令自查

```bash
# 1. 模拟通道在不在（生产环境应该是 404）
curl -s -o /dev/null -w '%{http_code}\n' -X POST https://你的域名.com/api/payments/mock-pay/x

# 2. 通道列表（生产环境不应出现 mock）
curl -s https://你的域名.com/api/payments/channels | python3 -m json.tool

# 3. 前端运行时配置（pay.mock 必须是 false）
curl -s https://你的域名.com/config.js

# 4. API 文档已关闭（应该是 404）
curl -s -o /dev/null -w '%{http_code}\n' https://你的域名.com/api/docs
```

本机部署也可以直接跑自检脚本，它会把上面这些配置项逐条标好：

```bash
bash deploy/verify.sh 你的域名.com
```

## 三、出问题怎么对

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `systemctl start` 失败，日志里一大段带方框的中文 | 生产环境有阻断级配置项 | 照着那段提示逐条改 `.env`，改完 `systemctl restart viora-ai` |
| 终端提示「生产环境禁止模拟支付」 | `ALIPAY_MOCK=1` | 改 0；还没签约就先写 `PAYMENT_CHANNEL=none` |
| 终端提示「生产环境禁止回显验证码」 | `MAIL_ECHO=1` | 改 0 并配好 SMTP |
| 终端提示「没配上游号池密钥」 | `MUSE_KEY` 空 | 填号池密钥 |
| 终端提示「没配管理员密码」 | `ADMIN_PASSWORD` 空 | 设一个 12 位以上强密码 |
| 终端提示「SMTP 未配置」 | 没配发信 | 配 SMTP，或设 `EMAIL_CODE_REQUIRED=0` 只用图形码 |
| 终端提示「支付通道没配齐」 | 没填支付宝又没关充值 | 填密钥，或写 `PAYMENT_CHANNEL=none` |
| 钱包页显示「收款通道未配置」 | 同上 | 同上（这是正常提示，不是 bug） |
| 用户注册提示「邮件服务还没配置」 | SMTP 没配 | 配 SMTP，或临时 `EMAIL_CODE_REQUIRED=0` |

## 四、部署脚本的变化

- `deploy/install.sh`：不再自动把 `ALIPAY_MOCK` 改成 1；安装完默认就是真实收款状态，
  没配支付宝就提示「充值不可用」，而不是偷偷开模拟。
- `deploy/verify.sh`：新增 `APP_ENV` / `MAIL_ECHO` / `PAYMENT_CHANNEL` / `SMTP_HOST` 四项检查，
  生产环境下 `ALIPAY_MOCK=1`、`MAIL_ECHO=1`、`PAYMENT_CHANNEL=mock` 直接标红（因为起不来）。
- `.env.example`：`APP_ENV=prod`、`ALIPAY_MOCK=0`、`MAIL_ECHO=0`，并且在注释里写明留空会拒绝启动。

## 五、代码位置

| 文件 | 作用 |
|---|---|
| `backend/app/guard.py` | 上线守卫：`violations()` 列出阻断项，`check_boot()` 在导入阶段拦截，`banner()` 打运行状态 |
| `backend/app/payments/gateway.py` | 生产环境不注册 `MockAdapter`；`mock_enabled()` 是唯一的模拟判定入口 |
| `backend/app/mailer.py` | `echo_mode()` 只认显式 `MAIL_ECHO=1`，不再有「非生产环境自动回显」 |
| `backend/app/routers/payment.py` | `mock_pay()` 内部再判一次，双保险 |
| `backend/app/main.py` | 导入阶段调 `guard.check_boot()`；生产环境关闭 `/api/docs` |
| `backend/app/db.py` | 生产环境不再使用内置默认管理员口令 |
