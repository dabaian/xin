# 短信接入说明（短信宝）

> 官方文档：<https://www.smsbao.com/openapi/213.html>
> 账号后台：<https://www.smsbao.com>

Viora AI 的注册、找回密码都走短信验证码。整条链路只有三个角色：

```
注册页 ──POST /api/auth/sms-code──▶ 后端 ──GET api.smsbao.com/sms──▶ 短信宝 ──▶ 用户手机
                                  ▲
                          极验 v4 先过一关（防刷）
```

---

## 1. 接口长什么样

```
GET https://api.smsbao.com/sms?u=USERNAME&p=PASSWORD&m=PHONE&c=CONTENT
```

| 参数 | 必填 | 说明 |
|---|---|---|
| `u` | 是 | 短信宝账号，本例 `qw951088` |
| `p` | 是 | **平台登录密码的 32 位 MD5**（不区分大小写），或后台生成的 ApiKey |
| `g` | 否 | 专用通道的产品 ID，不填走「通用短信产品」 |
| `m` | 是 | 手机号。群发用逗号分隔，一次不超过 99 个 |
| `c` | 是 | 短信内容，**必须 UTF-8 URL encode**，签名【】写在内容里 |

返回的是**纯文本**，不是 JSON。第一行 `0` 就是成功：

```
0
```

否则是错误码，见第 5 节。

> ⚠️ `p` 的坑：文档写的是「平台登录密码 MD5 后的值（32 位）」。
> 如果把登录密码明文填进去，接口会返回 `30 错误密码`。
> 这是 90% 的人第一次接入失败的原因。

---

## 2. 拿到 `p`（MD5）

短信宝后台的「登录密码」不是 `p` 的值，要先做一次 MD5：

```bash
python -c "import hashlib;print(hashlib.md5(b'你的登录密码').hexdigest())"
```

输出 32 位十六进制串，比如 `9cb2ff0273f048eab4ed796e84e8b588`，这个才是 `p`。

或者直接用 32 位 MD5 去 API 查一次余额，能返回 `0` 就说明对：

```bash
curl "https://www.smsbao.com/query?u=你的账号&p=你的32位MD5"
# 正确返回：
# 0
# 已发送条数,剩余条数
```

## 3. 写进 `.env`

```ini
SMSBAO_USER=qw951088
SMSBAO_KEY=9cb2ff0273f048eab4ed796e84e8b588     # 32 位 MD5，不是明文
SMSBAO_API=https://api.smsbao.com/sms
SMSBAO_QUERY=https://www.smsbao.com/query
SMSBAO_GOODS=                                    # 有专用通道才填
SMS_TIMEOUT=10

# {code} 是占位符，会被替换成 6 位验证码
SMS_TEMPLATE=【晟众远网络科技】您正在注册Viora AI平台账号，您的验证码是{code}，如非本人操作，请忽略本短信！
SMS_TEMPLATE_RESET=【晟众远网络科技】您正在找回Viora AI平台账号密码，您的验证码是{code}，如非本人操作，请忽略本短信！
SMS_TEMPLATE_LOGIN=【晟众远网络科技】您正在登录Viora AI平台账号，您的验证码是{code}，如非本人操作，请忽略本短信！

SMS_CODE_TTL=300     # 验证码 5 分钟有效
SMS_ECHO=0           # 生产必须 0（写 1 会被启动守卫拒绝）
MOBILE_REQUIRED=1
```

改完**必须重启后端**才会生效：

```bash
# Windows
start.bat
# Linux / macOS
./start.sh
```

## 4. 自检（配完先跑这个，别等到注册页试错）

```bash
cd backend
python tools/smstest.py                 # 只体检：账号、密钥形态、余额、模板长度
python tools/smstest.py 13800138000     # 体检 + 真发一条（会扣 1 条余额）
```

正常输出：

```
[OK]  是 32 位十六进制，符合「登录密码 MD5」的格式
[OK]  账号密码验证通过
      已发送 0 条，剩余 1760 条
[OK]  注册模板 54 字，按 1 条计费
[OK]  短信宝已接收（返回 0）
```

## 5. 返回码对照

| 码 | 含义 | 怎么修 |
|---|---|---|
| `0` | 发送成功（接口已接收） | — |
| `30` | 密码错误 | `SMSBAO_KEY` 要填 32 位 MD5，不是明文 |
| `40` | 账号不存在 | 检查 `SMSBAO_USER` |
| `41` | 余额不足 | 短信宝后台充值 |
| `43` | IP 地址限制 | 后台绑定了固定 IP，把服务器 IP 加白名单或解绑 |
| `50` | 内容含敏感词 | 改模板文案，或模板还没报备 |
| `51` | 手机号码不正确 | 手机号格式问题 |

后端会把这些码翻译成中文，直接显示在注册页的提示里，不用去猜。

## 6. 接口返回 0，但手机收不到 —— 大概率是这个

`0` 只代表**短信宝接收了请求**，不代表运营商投递成功。

国内短信的**前置硬条件**（文档原文）：

> 使用该接口时，必须提前在短信宝短信后台申请 **VIP 通道模板** 并且**联系客服报备**。

所以顺序是：

1. 登录短信宝后台 → 申请 VIP 通道模板（内容要和你 `.env` 里的 `SMS_TEMPLATE` 一致）
2. 联系客服报备这条模板
3. 报备通过后再发，才能真投递

没报备时的典型表现：接口返回 `0`，扣了费，手机上啥也没有。

另一个官方提醒：

> 测试时请使用正式内容进行测试，请勿给同一手机号连续发送相同内容，
> 运营商已进行规则调整以应对短信炸弹问题。

所以连续对同一个号发同样的文案，可能被运营商侧静默拦截 —— 这在测试阶段特别容易误判成「代码有问题」。

## 7. 官方要求的安全措施（本项目已满足）

文档原文：

> 网页应用用于手机验证，请务必增加图形验证（以防止被人利用，被用于短信轰炸用途）。

本项目的做法：

- 发码接口 `/api/auth/sms-code` 先过**极验 v4**（`GEETEST_ID` / `GEETEST_KEY`），
  极验没配时自动退回自绘图形码；
- 同一手机号 **60 秒冷却**、每小时最多 5 条；
- 同一 IP 每小时最多 20 条（`smscode.py`）+ 12 次（`security.sms_limiter`）；
- 一张验证码最多试错 5 次，超过即作废；
- 验证码只存 SHA-256 哈希，库里没有明文。

这四道闸是照着「防止被拿来刷短信」设计的，别为了省事关掉。

## 8. 计费

- 70 字以内按 1 条计费，超出按长短信拆分（`sms.py` 的 `ONE_SMS_CHARS`）。
- 当前注册模板 54 字、找回密码模板 56 字，都在 1 条内。
- 想看实际消耗：`python tools/smstest.py` 的余额那一行，或短信宝后台的发送记录。

## 9. 换通道（不想用短信宝）

短信发送全部收敛在 `backend/app/sms.py` 的 `send()` 里，换服务商只要改这一个函数：

```python
def send(mobile, code, purpose="register", minutes=5) -> dict:
    content = render(purpose, code, minutes)
    # 换成阿里云 / 腾讯云 / 容联云：
    #   1. 用它们 SDK 的 SendSms 接口，模板 ID + 模板变量
    #   2. 同样把 code_no != 0 翻译成中文报错
    #   3. 返回 {"echo": False, "chars": len(content)}
```

调用方（`routers/auth.py`）不用动，它只认 `sms.send()` 和 `sms.SmsError`。

## 10. 排查清单

按顺序对一遍，基本能定位：

1. `python tools/smstest.py` 能过吗？
   - 不过 → 账号/密钥/余额问题，看第 5 节
2. 余额在掉吗？
   - 不掉 → 请求根本没出去（后端没重启，或者 `SMS_ECHO=1` 走了回显）
   - 在掉但收不到 → 模板没报备，看第 6 节
3. 后端日志里有没有 `短信宝返回 xx`？
   - 有 → 按码查表
   - 没有 → 看 `短信宝请求：` 那行，确认 `m` 和 `u` 对不对
4. 换个手机号 / 换家运营商试试
   - 某个号收不到 → 该号被运营商拦了，不是系统问题
