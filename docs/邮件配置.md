# 邮件（SMTP）配置

注册和「邮箱验证码登录」都靠邮件发码。没配 SMTP 时，页面会弹：

> 邮件服务还没配置（SMTP_HOST / SMTP_USER / SMTP_PASS），暂时发不出验证码，请联系管理员

这就是还没填发信邮箱，**不是 bug**。按下面 3 步填完重启即可，全程约 3 分钟。

---

## 一、最快路径：用 QQ 邮箱发信

个人 QQ 邮箱就能发，每天几百封的量完全够用，不需要买企业邮箱。

### 1. 拿「授权码」（不是登录密码）

1. 网页登录 <https://mail.qq.com>
2. 右上角 **设置** → **账号**（新版叫「账号与安全 → 安全设置」）
3. 找到 **POP3/IMAP/SMTP/Exchange/CardDAV/CalDAV 服务**
4. 开启 **IMAP/SMTP 服务** → 按提示用手机发短信验证
5. 弹出的 16 位字符串就是 **授权码**，复制下来（只显示一次，丢了重新生成）

> ⚠️ 90% 的「登录被拒」都是这里填了 QQ 登录密码。必须是那串 16 位授权码。

### 2. 改 `.env`

```ini
SMTP_HOST=smtp.qq.com
SMTP_PORT=465
SMTP_USER=你的QQ号@qq.com
SMTP_PASS=刚才那16位授权码
SMTP_FROM=你的QQ号@qq.com
SMTP_SSL=1
SMTP_STARTTLS=0
MAIL_ECHO=0
EMAIL_CODE_REQUIRED=1
```

### 3. 重启并自检

```bash
# 先体检（只连不发）
python tools/mailtest.py

# 再真发一封到自己的邮箱
python tools/mailtest.py 你的邮箱@qq.com
```

看到 `发信链路完整可用 ✅` 就成功了，回注册页点「获取验证码」即可。

## 二、各类邮箱参数对照

| 邮箱 | SMTP_HOST | 端口 | SSL | STARTTLS | 密码填什么 |
|---|---|---|---|---|---|
| QQ 邮箱 | `smtp.qq.com` | 465 | 1 | 0 | **授权码** |
| QQ 邮箱（587） | `smtp.qq.com` | 587 | 0 | 1 | **授权码** |
| 163 邮箱 | `smtp.163.com` | 465 | 1 | 0 | **授权码** |
| 126 邮箱 | `smtp.126.com` | 465 | 1 | 0 | **授权码** |
| 腾讯企业邮 | `smtp.exmail.qq.com` | 465 | 1 | 0 | **客户端专用密码** |
| 阿里企业邮 | `smtp.qiye.aliyun.com` | 465 | 1 | 0 | 邮箱登录密码 |
| Gmail | `smtp.gmail.com` | 465 | 1 | 0 | **应用专用密码**（需开两步验证） |
| Outlook | `smtp.office365.com` | 587 | 0 | 1 | 账号密码（需开 SMTP AUTH） |

**465 和 587 二选一**，别同时开：

- 465 → `SMTP_SSL=1`、`SMTP_STARTTLS=0`（推荐，最省事）
- 587 → `SMTP_SSL=0`、`SMTP_STARTTLS=1`

> 云服务器（阿里云/腾讯云）默认封出站 **25 端口**，所以别用 25，一律走 465。

**163 / 126 的坑**：新号首次发信会退信并要求「设置客户端授权码」，同时 163 对陌生内容敏感，
第一封如果进了垃圾箱，把发件人加进白名单后续就正常了。

## 三、验证码相关开关

| 变量 | 默认 | 说明 |
|---|---|---|
| `EMAIL_CODE_REQUIRED` | 1 | 注册/验证码登录是否强制校验邮箱码。设 0 则整块隐藏（只剩图形验证码） |
| `EMAIL_CODE_TTL` | 600 | 验证码有效期（秒） |
| `MAIL_ECHO` | 0 | **仅本地调试**：没配 SMTP 时把验证码回显到接口响应里。生产环境设 1 会直接启动失败 |

发码频率限制写死在 `backend/app/emailcode.py`，不用配：

- 同一邮箱 **60 秒**冷却
- 同一邮箱 **每小时 5 封**
- 单张码最多试错 **5 次**，第 6 次直接作废

## 四、报错对照表

`tools/mailtest.py` 会把下面这些情况直接指出来，也可以自己对着看：

| 报错 | 原因 | 怎么修 |
|---|---|---|
| `SMTPAuthenticationError 535` | 密码填错（用了登录密码） | 换成授权码 |
| `Connection unexpectedly closed` | QQ / 163 在账号或授权码不对时**直接断连** | 同上，99% 是 `SMTP_PASS` 不是授权码 |
| `SMTPAuthenticationError 530` | 邮箱后台没开 SMTP 服务 | 去设置里开启 IMAP/SMTP |
| `Connection refused / timeout` | 端口不通、被防火墙拦 | 换 465；云服务器查安全组出站规则 |
| `SSLError WRONG_VERSION_NUMBER` | 明文端口当 SSL 连 | 465 用 `SMTP_SSL=1`，587 用 `SMTP_SSL=0` |
| `550 Sender rejected` | 发件人和登录账号不一致 | `SMTP_FROM` 留空，或填成和 `SMTP_USER` 相同 |
| `554 / 5.7.1 spam` | 内容被判定垃圾邮件 | 换域名邮箱，或先给自己发一封养号 |
| 收件箱没收到但工具说成功 | 进了垃圾箱 / 收件服务器延迟 | 查垃圾箱，通常 1 分钟内到 |

## 五、生产环境的两条硬要求

1. **`MAIL_ECHO=0`**
   开着它等于把验证码直接返回给调用方，注册等于没有验证。`APP_ENV=prod` 时写 1 会被
   `backend/app/guard.py` 拦下，服务起不来——这是故意的。

2. **`.env` 权限 600**

   ```bash
   chmod 600 /opt/viora-ai/.env
   ```

   授权码等同于邮箱密码，别提交到 Git。

## 六、没有邮箱、又想让用户能注册？

三种选择，按推荐度排序：

| 方案 | 做法 | 代价 |
|---|---|---|
| 买企业邮箱 | 腾讯企业邮免费版（1 个账号）+ 自己的域名 | 需要域名，最正规 |
| 关掉邮箱验证 | `EMAIL_CODE_REQUIRED=0`，只留图形验证码 | 改动最小，但验证强度低 |
| 换短信验证码 | 在 `auth.py` 的 `/email-code` 里改调短信服务商 | 要买短信包，约 0.04 元/条 |

第一种最省事：企业邮免费版能发、能收、能配 SPF，授权码流程和 QQ 邮箱一样。
